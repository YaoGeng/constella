## 1. 拍板记录（用户，2026-11-08）

- 上一轮调研提出的新决策点 **D-12 ~ D-18 全部采纳**（Office/HTML 输出、MCP host+节点、skill loader、computer use、命令面板、ai.subagent、流程反向发布 MCP server）。
- 输出节点家族**补充 md（Markdown）输出**（`out.md`），与 office/html 同族。
- 分层总原则（调研 8.1，随批生效）：**执行与安全 → 应用本体内核；可组合 IO 单元 → 平台内置节点（同注册表、同 N1~N8、可上广场）；知识/流程（skill/命令）→ 文件级用户内容，本体 loader 加载、工坊消费；不新建第三扩展体系。**

## 5. ctx 能力集演进原则（防扩散红线）

- **ctx 表面保持最小**：V1 冻结集（browser/llm〔含多模态〕/im/vault/agent/log/sleep/emit/net/file）**不再向自定义脚本开放新能力**。新内核一律以「平台内置节点」形态暴露（节点内部实现走主进程 API），不开 ctx 口子。
- **例外仅一个**：`ctx.mcp`（V2.0 评估，**正式化为决策点 D-19**，注册于 00b §2）——若 AI 现场开发的节点确需直接调 MCP 工具，走与 mcp.call 相同的 host 审批通道后开放；默认不开，先验证节点链（mcp.call→自定义节点）是否够用。
- **computer use 永不进 ctx**：键鼠控制权不下放给任意脚本（沙箱白名单体系红线）；只经 computer.* 平台节点 + 授权清单。
- 每次扩 ctx = 00 A-4.3 升版留痕 + 04 评审（与 G-2 同流程）。

## 6. 逐能力规划卡（十条，含验收判据）

### 卡 1 · md 输出（V1.1，用户点名新增）
- 定义：`out.md` 节点把上游 data 经模板渲染为 Markdown 文件落盘；**同时作为 AI 生成报告的默认格式**（工坊生成「报告/日报」类节点时优先产 out.md）。
- 验收：MA-5 账号健康日报流程加 out.md 出口 → 运行后生成 .md，字段占位符全部替换、无残留 `{{`；生成/追加两模式行为正确；文件在 out 节点输出路径可被 Typora/VSCode 正常渲染。

### 卡 2 · html 输出（V1.1）
- 定义：`out.html` 单文件 HTML（内联样式，星空主题模板一套内置）；数据→模板→写盘。
- 验收：同一日报数据双出口（out.md + out.html）产物一致；内联资源开关生效（单文件离线可开）；模板占位与 for 循环块渲染正确。

### 卡 3 · Office 输出（V1.1）
- 定义：out.docx/out.xlsx/out.pptx；docx 用内容映射 JSON（段落/表格/图片引用），xlsx 用 sheets 定义，pptx 用幻灯片序列映射；exceljs 加包装层。
- 验收：三件套各跑一条验收流程（docx=报告、xlsx=多 sheet 明细、pptx=5 页总结）；生成文件 Office/WPS 打开无修复提示；超过 1MB 数据量时生成 ≤10s；exceljs 包装层单测覆盖（隔离其 API 面，备选库可替换）。

### 卡 4 · 模型场景路由（V1.1）
- 定义：设置中心新增「场景路由」：工坊规划/流程规划、节点内 ai.llm、图判（多模态）、子代理四场景各自绑定模型 profile；D-4 的 baseUrl/apiKey 机制不变。
- 验收：改工坊模型为强模型、节点 llm 为廉价模型后，两处调用日志显示各自命中；某 provider 失败时按场景降级提示（不静默换模型）。

### 卡 5 · MCP host + mcp.call 节点（V2.0，D-13）
- 定义：本体 McpHost（连接配置面=设置中心新页：stdio/HTTP、OAuth、工具级白名单、输出 token 上限）；mcp.call 节点参数面由 tools/list 动态生成（下拉工具+schema 表单+JSON 兜底）；AI 工坊规划来源加第四候选 🔌MCP（库/广场/现场开发/MCP 工具）。
- 验收：接入 MCP 官方 filesystem server → 下拉出现其工具 → 调用 read 返回数据入库；未审批 server 不可用；工具输出超限截断并告警；断连后节点失败走 failed 出口（不挂死 run）。

### 卡 6 · skill loader（V2.0，D-14）
- 定义：兼容 agentskills.io：`~/.constella/skills`（用户）与项目 `.agents/skills` 扫描 SKILL.md；渐进披露（name+description 常驻工坊上下文，调用载全文，预算上限可配）；skill 影响工坊生成行为（如「小红书风控红线」skill → xhs 节点生成时带频控参数）；skill 可打包进节点 zip 广场分发（plugin=pack 形态）。
- 验收：装一个示例 skill 后，同样的工坊 prompt 生成的节点参数包含 skill 规定的约束；skill 描述总量超预算时自动折叠；`$skill-name` 显式调用与自然语言隐式调用均可。

### 卡 7 · 命令面板（V2.0，D-16）
- 定义：Ctrl+K 面板，索引：运行流程/插入节点/调用 skill/打开设置/切模型；命令是**skill 与流程的显式入口**，不设独立命令文件格式（Claude Code/Codex 已证伪独立命令体系）。
- 验收：面板可模糊搜到流程与 skill 并触发；键盘全程可操作；不存在「命令」独立目录。

### 卡 8 · ai.subagent 子代理节点（V2.0，D-17）
- 定义：隔离上下文的 LLM 任务环节点：指令+工具集（可勾选节点库/MCP）+maxTurns+超时重试（N6）；复用工坊内核的任务环实现。
- 验收：子代理完成一次「查库→判定→返回结构化结果」任务并交付下游；maxTurns 打断后走 failed 出口；与 human.review 断点组合场景可用。

### 卡 9 · 流程反向发布为 MCP server（V2.0，D-18）
- 定义：本机星丛作为 MCP server（stdio+HTTP），把选定流程暴露为工具（入参=触发节点参数，返回=终态 lane 数据）；与广场分发互补（流程即工具）。
- 验收：外部 MCP client（如 Claude Code）连接星丛并调用一条流程工具，得到运行结果；并发调用排队不互踩（与 A-6.1 同流程不重复跑语义一致）。

### 卡 10 · computer use 系统级（V2.x 三级，D-15）
- 定义与 gate：
  - ①view：`computer.screenshot` + UIA 只读控件树探测（无输入合成）；验收=对授权窗口截屏+读出控件树正确。
  - ②click：`computer.click/type`，逐应用授权清单（终端/IDE 默认等效 shell 拒绝、浏览器可 view-only）；验收=授权应用内完成一次真实点击任务，Esc 全局中止生效，操作审计落库。
  - ③full：白名单应用内自主操作循环（视觉模型）；验收=完整任务 demo + 审计回放 + 敏感应用拦截矩阵全绿。
- 红线：不进 ctx；Windows 仅前台限制写入非功能说明（ChatGPT 桌面版同款限制，调研 5.1）。

## 7. 广场与治理联动
