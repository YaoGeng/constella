## 1. 产品概述

### 1.1 产品定位

**星丛 Constella 是一个「AI 持续开发流程节点」的桌面自动化平台：AI 负责持续开发可执行节点，人把节点在画布上编排成流程（星座）运行。** 对标 n8n / Zapier 的工作流编排形态，核心差异在**节点供给侧**：

- n8n 的节点由平台与插件生态预置，用户等待生态供给；
- 星丛的节点**由用户自建或 AI 现场开发**，以 **zip 资产包**（manifest + 节点定义 + 可执行脚本 + 默认配置 + 依赖声明）在本机与广场之间流通（demo.html L10-11、L2205 注释：「库与广场都接不上的缺口正好用现场开发补齐，这是星丛区别于 n8n 的核心卖点」）。

按 00 A-4.8 的节点供给模型（v1.1 修正）：

- **内置积木**：12 个平台内置节点类型（demo L863-892），是画布表达的原子词表；
- **示例资产**：9 个自研强节点与 9 条种子流程（demo L893-938、L1080-1226）仅用于演示「AI 创作产物的形态」，**不是内置依赖，不构成正式版的供给承诺**；
- **核心供给**：正式版节点的真实供给 = **用户手动自建 + AI 现场创作**，两条路径共用同一能力模型（N1~N8，见第 5 章），产物统一为满足该模型的 zip 资产包。

### 1.2 目标用户

| 用户 | 场景 | 说明 |
|---|---|---|
| C 端用户（自动化使用者） | 用画布把节点编排成流程并运行：网页采集、内容运营、数据备份、批量申报等 | 主要角色；无需编程即可通过流程工坊一句话获得整条流程 |
| 节点作者（节点创作者） | 手动定义或与 AI 对话开发自定义节点，入库复用、导出 zip、发布到广场 | 与 C 端用户**同一账号的两个状态**（⚠ 决策点 D-1 默认，见第 11 章），不设独立注册 |
| 管理员 | 广场审核（通过/驳回）、用户管理（列表/封禁）、包管理（详情/下架）、运营看板 | admin 端独立账号（⚠ D-1/D-7 默认） |

### 1.3 核心价值主张

1. **节点即供给**：缺什么节点，AI 现场开发（py/ts 脚本 + 配置打包成节点，生成即入库沉淀）——「开发即沉淀」闭环（demo L2283-2296）。
2. **数据流并行引擎**：流程间并行 + 流程内 lane 分支并行，汇合/死路径消除语义冻结（A-6.2），多城市并行办理类业务一条流程表达（demo L1739 典型场景注释）。
3. **human-in-the-loop**：跑到断点暂停等人（对齐 LangGraph interrupt/Command(resume) 模式，demo L1962-1965），人工把关后才继续。
4. **资产流通**：节点/节点包/整条流程以 zip 资产包导出、导入、发布、安装，社区广场分发（A-12/A-13）。
5. **本地优先**：编排、运行、存储全部本地可用，联网仅增强（广场/账号，见第 8.3 节）。

## 2. 用户与角色

角色定义与 00 G 章决策点 D-1 默认值一致（⚠ 默认，封版前可推翻）：

| 能力 | C 端用户 | 节点作者（同账号另一状态） | 管理员 |
|---|---|---|---|
| 本地编排/编辑/保存/版本/撤销 | ✅ 离线可用 | ✅ 同左 | —（不使用 client 业务功能） |
| 本地运行流程（CDP/脚本） | ✅ 离线可用 | ✅ 同左 | — |
| AI 双工坊（自配 Key 直连） | ✅ | ✅ 同左 | — |
| zip 导入/导出、节点入库 | ✅ | ✅ 同左 | — |
| 广场浏览/下载/安装 | 浏览匿名开放；下载/安装需登录（D-1 原文；00 v1.2 X-6 裁定口径：浏览匿名开放；下载/安装/发布需登录） | ✅ 同左 | ✅（审核视角） |
| 广场发布（node/pack/flow） | ❌ | ✅ 需登录（首次发布即视为进入作者状态） | ❌ |
| 广场审核（通过/驳回+理由）、下架 | ❌ | ❌ | ✅ |
| 用户列表/封禁、运营看板 | ❌ | ❌ | ✅（admin 端，D-7 最小集） |
| 账号体系 | 邮箱注册+登录（server JWT，D-1） | 同一账号 | admin 独立管理员账号 |

权限差异要点：**节点作者与 C 端用户是同一账号的两态**，无独立注册与升级流程；「作者态」由发布行为激活。client 本地全部能力离线可用，仅广场消费/发布与账号操作依赖 server。

## 3. 技术约束与非目标

### 3.1 用户冻结的技术约束（逐字收录自 00 第 2 章，不可协商）

> - C端：React 19+、Electron 45+、TailwindCSS；UI 库与画布（节点编辑器）库需做技术选型（选型结论见 D-9 决策记录）
> - 管理端：React 19+、antd 6+
> - server：参考 https://github.com/YaoGeng/Hono-Prisma-PostgreSql-Template（Hono + Prisma + PostgreSQL）

三端职责边界（与 00 第 2 章一致）：

- **client**（C端桌面应用）：画布编排、双 AI 工坊、运行引擎与 CDP/沙箱执行、本地存储、zip 打包/导入、广场消费端（浏览/安装/发布入口）。
- **admin**（管理端）：广场审核、用户管理、节点包管理、运营数据看板。
- **server**（服务端）：账号体系、广场服务端（包上传/存储/下载/列表/审核状态机）、公共数据。

### 3.2 非目标（V1 明确不做，理由见第 10 章排除清单）

云同步与多端数据同步；多语言/i18n；深色/浅色主题切换（demo 仅深色，L24-39 token 体系即深色）；移动端与浏览器纯 Web 版；多人协作编辑；广场计费/支付/分成；自动安全扫描（D-2：延后，V1=人工审核）。

### 4.1 A-1 全局框架与导航

#### PRD-A1-01 顶栏与三导航（覆盖 A-1.1）
- 优先级 P0 · 归属端 client
- 用户故事：作为 C端用户，我要在顶栏一眼看到品牌/版本徽标、工作流/系统设置/任务中心三个导航，以及任务中心上的并行任务数徽标，以便随时掌握全局状态并快速切换工作区。
- 验收（GWT）：
  - Given 应用已启动，When 渲染完成，Then 顶栏含品牌「星丛 Constella」+ 版本徽标（demo L599 为 `DEMO`，正式版显示 semver 版本号），导航为「工作流 / 系统设置 / 任务中心」三项（demo L601-605）。
  - Given 有 2 个 run 处于 running 状态，When 查看任务中心导航按钮，Then 徽标显示「2」（demo renderNavBadge L2763-2767：徽标仅在 n>0 时显示）。
  - Given 任务中心已打开，When 点击「工作流」导航，Then 任务中心抽屉关闭且工作流高亮（demo L2679）。

#### PRD-A1-02 环境状态 pills（覆盖 A-1.2）
- 优先级 P0（pill 本体）/ P1（真实化）；MCP 真实集成 = P2（排除）
- 用户故事：作为 C端用户，我要通过顶栏三个状态 pill（电脑环境 / CDP 连接 / MCP 工具清单）确认本机执行环境可用，以便在运行前排除环境故障。
- 验收（GWT）：
  - Given 应用启动，Then 顶栏显示三 pill：电脑环境、CDP（已连接/未连接）、MCP（demo L607-611）。
  - Given CDP 正常，When 点击 CDP pill，Then 状态在已连接/未连接间切换，运行中的 cdp.* 节点在断连后失败终止（demo L2650-2658 演示路径；正式版=真实检测，见 B-9/B-14 表态）。
  - Given 点击 MCP pill，When popover 展开，Then 显示已挂载工具清单（demo L745-752：5 工具）。
- P1 边界：demo 三 pill 均为假数据（点击电脑环境弹 mock toast L2659）；正式版语义=真实系统信息（os/内存/运行时版本）、真实 CDP 连接检测、真实 MCP 挂载清单；MCP 真实集成按 00 A-1.2 列为 P2 排除，pill 仅展示清单占位。

#### PRD-A1-03 底栏身份与保存状态（覆盖 A-1.3）
- 优先级 P0（身份真实化按 ⚠ D-1） · 归属端 client（身份与 server 跨端）
- 用户故事：作为 C端用户，我要在底栏看到当前身份、保存状态（已同步/未保存/自动保存中）、自动保存徽标、会话时长与版本号，以便确认我的工作已被持久化。
- 验收（GWT）：
  - Given 无未保存改动，Then 底栏 storeState 显示「已同步 · HH:MM」（demo L1317）。
  - Given 产生未保存改动且自动保存关闭，Then storeState 显示「● 未保存 — 点击保存」并闪烁（demo L1307、L476 blink 动画）；When 点击该徽标，Then 立即保存（demo L3074）。
  - Given 自动保存开启且产生改动，Then 徽标先显示「自动保存中…」，800ms 防抖到点后落盘并回到已同步（demo L1306、L1311）。
  - Given 登录用户为 Yeager，Then 底栏显示头像/昵称/角色徽标（demo L717 固定「Yeager·管理员」为 mock；正式版=登录态昵称+角色，未登录显示本地访客态，⚠ D-1）。
  - Given 会话进行中，Then 会话时长每 1s 心跳刷新（demo L3090-3092）。

#### PRD-A1-04 全局 toast、Esc 层级收起、关闭脏拦截（覆盖 A-1.4）
- 优先级 P0 · 归属端 client
- 用户故事：作为 C端用户，我要所有操作反馈以 toast 呈现、Esc 能层层收起浮层、关闭应用前被未保存改动拦住，以便操作可感知且不误丢工作。
- 验收（GWT）：
  - Given 任意操作触发提示，Then toast 出现在底部居中，约 2.6s 后淡出（demo L1271-1277）。
  - Given 同时存在 CDP 查看窗、抽屉、任务中心、弹窗，When 依序按 Esc，Then 按「CDP 查看窗 → 抽屉 → 任务中心 → 弹窗（含 MCP popover）」层级逐一收起（demo L1573-1577）。
  - Given 有未保存改动，When 尝试关闭窗口/页面，Then 弹出原生确认框拦截（demo beforeunload L3083-3086；Electron 下换为原生对话框确认，交互语义不变）。

### 4.2 A-2 流程管理

#### PRD-A2-01 流程下拉切换与脏闸（覆盖 A-2.1）
- 优先级 P0 · 归属端 client
- 用户故事：作为 C端用户，我要用下拉在流程间切换，且当前流程有未保存改动时被拒绝切换，以便不丢改动。
- 验收（GWT）：
  - Given 流程 A 有未保存改动（dirty），When 在下拉选择流程 B，Then 弹 err toast「有未保存改动 — 先保存或取消再切换」且下拉回弹到流程 A（demo L1700-1702 renderFlowSelect 重绘回弹）。
  - Given 流程 A 无未保存改动，When 切换到流程 B，Then 画布重绘、fitView、模式回 view、日志面板切换过滤、撤销栈清空（demo L1702-1708）。
  - Given 当前流程 dirty，Then 下拉中当前流程名后缀「●」（demo L1697）。

#### PRD-A2-02 新建流程（覆盖 A-2.2）
- 优先级 P0 · 归属端 client
- 用户故事：作为 C端用户，我要通过命名弹窗新建流程（名称上限 30 字），以便开始新自动化。
- 验收（GWT）：

#### PRD-CUSTOM-N6 运行策略
- 优先级 P0（超时+重试）；失败分支=V1 支持（本 PRD 表态，见下） · 归属端 client
- 用户故事：作为节点作者，我要为节点声明超时、重试次数与间隔、失败处理策略，以便脆弱的外部依赖不拖垮整条流程。
- 验收（GWT）：
  - Given 节点声明 timeout=Xs，Then 执行超 X 即强杀（沙箱层，⚠ D-3）并按失败策略处理。
  - Given 声明 retry=N / interval=Ms，Then 失败后按间隔重试至多 N 次，重试耗尽进入失败处理。
  - Given 节点**显式声明 timeout=0**，Then 不设超时守护：节点可无限期执行直至自身返回/失败/被终止指令结束（X-4，01a 输入⑤；01a MA-2 dm-send「超时=不设」即此语义）；显式 timeout=0 与「未配置 timeout 字段走默认值 30s」为两种不同语义，实现与文档必须区分。
  - Given 节点**显式声明 retry=0**，Then 显式禁用重试：首次失败即进入失败处理（X-4；01a MA-2「宁漏勿重」即此语义）；显式 retry=0 与「未配置 retry 字段默认允许重试」为两种不同语义，实现与文档必须区分。
  - **失败分支表态：V1 支持。** 节点可声明「失败→专用出边」（如 fail/dead-letter）：执行失败（含重试耗尽）时向该出边交付错误数据、流程继续；未声明失败分支的节点失败按 A-6.2 冻结语义终止 run。边界：环境级故障（CDP 断连、run 级终止指令）不适用失败分支，仍按冻结语义失败终止（与 demo L1911-1917 一致）。理由：强节点「自带路由」特征已内含失败-降级路径语义（blocked/miss/escalated 均为其形态），引擎多出边路由已冻结支持，边际成本低、与 mantis 场景（MA-4 escalated 人工接管）直接对齐。
  - Given demo 的 AI 优化路径「追加：失败重试 ×3 · 超时 10s」（demo L2400），Then 正式版=写入 N6 策略字段而非自由文本参数。

#### PRD-CUSTOM-N7 IO 契约声明
- 优先级 P0（最低限度：输出字段名+类型+示例） · 归属端 client
- 用户故事：作为节点作者，我要声明节点的输入期望与输出 schema，以便下游参数引用、AI 规划与校验器有据可依。
- 验收（GWT）：
  - Given 节点声明输出 schema（字段名/类型/示例值），Then 抽屉 io 区按声明展示（B-13 表态的落地形态）。下游参数引用按 00 v1.2 T-4 裁定收窄：**V1=声明+校验器静态校验+AI 规划期映射**（规划阶段按声明完成上下游字段映射并固化为节点参数），`{{nodeId.field}}` 运行时求值延后 Vx（运行时求值需引入参数求值引擎与环检测，mantis 五流程上下游衔接均经 input 直传+断点合并，无此依赖）。
  - Given 多出口节点（N2 出口≥2），Then 可**按出口分别声明输出 schema**（X-5，01a 输入⑥）：各出口一组字段名/类型/示例；用例=MA-4 组合节点 replied/escalated/skipped 三态输出不同结构。未按出口分声明的多出口节点退回单一 output schema，抽屉展示与校验器按单 schema 核对。
  - Given 流程工坊规划，Then AI 仅引用节点已声明的输出字段做参数映射；未声明 IO 的节点参与规划时按保守策略（透传 input）处理。
  - Given 流程结构校验器运行，Then 用声明核对「上游输出 ↔ 下游输入期望」的兼容性并报告冲突（A-17.8）。

### 5.3 路径①：手动自建路径（PRD-CUSTOM-PATH1）

- 优先级 P0（正式版新增；demo 无完整对应物，依据 00 A-4.7/A-4.8「核心供给=用户自建」） · 归属端 client

- 入口：节点抽屉 create 态「✨自定义」入口扩展为双分支——「让 AI 开发」（跳节点工坊，保持 demo 冻结行为，demo L2094-2100）与「手动定义」（打开自定义节点编辑器）；节点库「＋节点」同入口。不改变 demo 冻结的 ✨ 入口跳转语义，仅在该入口增加第二分支。
- 六个环节与验收（GWT）：
  1. 元信息：Given 编辑器元信息页，Then 可定义 N1 全部字段；名称必填校验。
  2. 端口：Given 端口页，Then 可增删入口/出口并为出口命名（N2）；画布预览实时反映端口布局。
  3. 参数 schema：Given schema 页，Then 以表单方式定义 N3 字段（类型/默认值/必填/校验/help/分组），并提供 schema 预览（即未来抽屉表单的渲染结果）。
  4. 脚本编辑器：Given 脚本页，Then 提供 py/ts 代码编辑（**语法校验=V1 必须**：保存前语法校验并拦截错误；**语法高亮=P2 增强**——00 v1.2 X-8 裁定，V1 为等宽字体纯文本编辑区；契约模板注入：run(ctx) 头与 PARAMS 默认值块，与 bundleCode 生成物同构，demo L1027-1050）；编辑内容即资产包 scripts/ 的真实内容（非模板拼接）。
  5. config：Given 配置页，Then 编辑 config/*.yaml 默认值（与参数 schema 键一致，运行时抽屉参数覆盖，demo L1051-1055 语义）。
  6. 入库与落盘：When 完成定义并保存，Then 生成满足 N1~N8 的节点定义：注册进本地类型注册表（custom 类型）、入库（含脚本元信息）、可直接加入画布；导出时按 A-4.3 契约成包。
- 完整性验收：Given 手动自建的节点，When 走导出→(他机)导入→运行全链路，Then 与内置强节点行为一致（noScript 闸同样生效）。
